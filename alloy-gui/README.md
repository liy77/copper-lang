# Alloy GUI — native host + dual-mode binary

The distributable **`alloy`** binary: works as a **command-line tool** and as a
**graphical application** (GUI built in MUI). Mirrors the `installer-gui` pattern:
the UI lives entirely in `alloy.mui`, and this crate is the native host that links
the mocida runtime + the backend.

> This crate is **not** a member of the copper-lang workspace (it links mocida,
> which the portable crates cannot). Compile it explicitly.

## Modes

```sh
alloy run file.crs     # interprets in the terminal (reuses the alloy-vm crate)
alloy file.crs         # same (direct path)
alloy update           # headless self-update
alloy                  # (no args) opens the GUI
alloy gui              # same
```

The GUI has three areas: **Playground** (editor + Run + output), **File runner**
(open a `.crs` and run it) and **Update** (check/install a new version).

## Layout

```
alloy-gui/
├── alloy.mui          The entire UI (declarative MUI). Signals driven by the host.
├── backend.rs         Logic: run_source (uses alloy-vm), read_file, updater. std-only.
├── app.bundle         Name/id + icon (mocida://alloy-icon.png).
├── assets/            alloy-icon.png / alloy-icon.ico (see assets/README.md).
├── build.rs           Embeds the .ico into the .exe (winresource, Windows only).
├── packaging/
│   └── make-app.sh    Generates Alloy.app + Alloy.icns on macOS.
└── src/main.rs        Dual-mode: CLI passthrough + MUI host.
```

## Build prerequisites

The host links the mocida runtime via the `mocida-rs` workspace crates, which must
be a sibling of this repo:

```
<root>/copper-lang/        (this repo)
<root>/mocida/mocida-rs/   (mocida runtime)
```

And the `mocida-sys` variables (path to headers/native lib):

```sh
export MOCIDA_INCLUDE_DIR=/path/to/uikit/headers
export MOCIDA_LIB_DIR=/path/to/libmocida
```

## Build

```sh
# binary (GUI + CLI)
cargo build --release --manifest-path alloy-gui/Cargo.toml
# → alloy-gui/target/release/alloy   (+ libmocida.dylib/.dll beside it)

# macOS: package as Alloy.app (with icon)
alloy-gui/packaging/make-app.sh
```

On Windows `build.rs` embeds `assets/alloy-icon.ico` into the `.exe`. On macOS the
icon comes from the `Alloy.app` generated by the script.

## Status

- **CLI**: complete (reuses `alloy-vm`).
- **GUI**: working — compiles and runs against the real mocida runtime. Light
  "angelic" white/gold theme matching the icon; Playground (TextArea editor +
  Run + output), File runner (native `rfd` file dialog), Update tab. Features
  `.mui` hot-reload, dynamic window resize, and scroll.
- **Updater**: detects the latest GitHub release (`REPO_SLUG = liy77/copper-lang`)
  and self-replaces the binary — but only works once **binary assets** are
  published on the release (the source tarball alone has nothing to download).
  Run `scripts/release-alloy.py` to produce per-target binaries to attach.

### Build/run notes (mocida)

Needs the sibling `mocida-rs` workspace and its env vars — see CLAUDE.md
"Alloy GUI host (mocida)". On macOS, omit `renderer:` (Vulkan is unavailable;
mocida auto-picks Metal). mui-runtime quirks worked around in `alloy.mui`:
Button colors must be literal (no `if`), use `TextArea` for multi-line, register
`mocida://` assets with absolute paths, and the host drives resize/hot-reload by
polling each tick.
